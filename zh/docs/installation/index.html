安装

这份指南带你从一个空目录走到 Job Radar 跑起来：看板、AI 打分，以及（如果你需要）Telegram 推送和手机访问。除非特别说明， 下面的命令都在项目目录里执行（也就是有 package.json 和 compose.yaml 的那个目录）。

第 1、3、5、6 步是主干；标了“可选”的都可以以后再做。

开始之前

Section titled “开始之前”

需要什么

版本 用来做什么

pnpm 11（版本写在 package.json 里） 给辅助命令装依赖
git 较新的版本即可 获取代码，以后升级
磁盘空间 几 GB 镜像（runner 镜像里带一个无界面浏览器）和数据库

以后再准备也可以的：

  • Telegram：推送到手机。
  • Tailscale：在手机上打开看板。

macOS、Linux、Windows

Section titled “macOS、Linux、Windows”
  • macOS 是 Job Radar 每天实际在跑的平台。想让 Mac 无人值守（登录时启动 Docker、断电后自动开机、外接硬盘），再看 host-setup.zh.md。
  • Linux 上所有部分都一样能跑；CI 里会在全新的 Ubuntu 上从零装一遍。区别有两处：容器以你的用户身份运行（PUID / PGID，第 3 步）， 辅助脚本把 AI worker 装成 systemd 用户单元而不是 launchd 服务（第 5 步）。Linux 主机清单见 host-setup.zh.md 第 10 节。
  • Windows：全部在 WSL2 里跑，项目放在 Linux 文件系统里（不要放在 /mnt/c 下），并打开 Docker Desktop 的 WSL 集成。 步骤和 Linux 一样，见 README 的平台说明。

2. 可选：创建 .env

Section titled “2. 可选：创建 .env”

每个变量都有能用的本地默认值，这一步可以先跳过。

要放密钥的时候才需要 .env：Telegram bot token、AI 的 API key、付费或需要 key 的来源（JSearch、Tavily、Bright Data、Apify、 Gmail）、换一个数据库密码、给看板加额外的主机名。每个变量在 .env.example 里都有说明。.env 被 git 忽略：不要提交它， 也不要把内容贴到任何地方。

4. 登录你的 AI（可选，推荐）

Section titled “4. 登录你的 AI（可选，推荐）”

在这台机器上你自己的终端里做。CLI 本身怎么安装，看它们各自的官方说明。

AI 登录 检查
Claude（订阅） 运行 claude，输入 /login，按提示完成后退出 claude auth status 显示 loggedIn: true
Codex（订阅） codex login codex login status 显示 Logged in
API key 在 .env 里填 ANTHROPIC_API_KEY、DEEPSEEK_API_KEY 或 MIMO_API_KEY（DeepSeek 和 MiMo 还要在 ai.yaml 里设 enabled: true） 第 5 步之后运行 pnpm ai:probe

订阅命令行不按 token 计费；每天的调用上限（默认 codex 200 次、claude 100 次）保护你的额度。API 只有在命令行都用不了时才会用到， 到 ai.yaml 里 monthly_api_budget_usd 的月预算就停。不要把订阅 token 放进 .env 或容器：AI worker 直接用你的命令行登录。 详见 ai-providers.zh.md。

5. 启动 AI worker

Section titled “5. 启动 AI worker”

AI worker 是跑在你机器上（不在 Docker 里）的一个小 Node 进程。它从数据库里认领所有 AI 请求，用你的命令行登录或 API key 执行， 写回结果，再发 Telegram 推送。

让它一直开着。最好在向导的 AI 那一步之前就启动，这样向导里的 Test（测试）按钮才有回应。worker 没开时，AI 请求只是排队： /sources 上的 AI worker 卡片显示“无响应”，三分钟后 runner 会发一条 Telegram 告警（如果开了 Telegram）。

一个数据库只跑一个 AI worker；第二个会以退出码 3 退出，并提示 another ai-worker is running against this database。 只想把队列处理一遍就退出：pnpm ai-worker --once。

在后台常驻

Section titled “在后台常驻”

先把终端里那个停掉（Ctrl-C），再装成登录时启动、崩溃后自动重启的服务。同一个脚本两个系统都能用：macOS 上是 launchd 服务， Linux 上是 systemd 用户单元（job-radar-ai-worker.service）。

检查一下：

升级 Node 或挪了 claude / codex 的位置之后，再运行一次这个脚本。卸载服务：scripts/ops/uninstall-ai-worker.sh。

在 Linux 上这个脚本需要 systemd 用户会话：从正常登录的终端运行，不要经 sudo、su 或 cron。没有用户会话时（容器里、没开 systemd 的 WSL）它会说明原因，什么都不改；这时用你习惯的进程管理方式，比如一个后台 tmux 会话：tmux new -d -s jobradar-ai 'pnpm ai-worker'。 细节（包括项目放在外接硬盘时的日志、手动安装用的单元模板）见 host-setup.zh.md（macOS 第 6b 节，Linux 第 10 节）。

7. 可选：Telegram 推送

Section titled “7. 可选：Telegram 推送”

Telegram 在你设置好之前是关着的。向导里跳过 Telegram 这一步，它就保持关闭；没打开的推送 doctor 也不会报。

  1. 在 Telegram 里打开 @BotFather，发送 /newbot，按提示起名，复制 token（形如 123456:ABC-...）。
  2. 打开你的新 bot，点 Start，随便发一条消息。
  3. 在浏览器里打开 https://api.telegram.org/bot<token>/getUpdates，找到 "chat":{"id":...}，这个数字就是 chat id。 这个链接里有 token，不要发给别人。
  4. 把两个值写进 .env：
  5. 重启容器和 AI worker，让它们读到新值：先 docker compose up -d，再重启 worker（macOS： launchctl kickstart -k gui/$(id -u)/io.jobradar.ai-worker；Linux 用 systemd：systemctl --user restart job-radar-ai-worker； 在终端里跑的：Ctrl-C 后重新启动）。
  6. 发一条测试：pnpm telegram:test。收到“✅ Job Radar”就说明通了。

在这台机器上，看板不用登录。你 tailnet 里的每台设备也都能访问它；所以如果有别人共用你的 tailnet，或者你把它开放到局域网、放到反向代理后面， 先设一个口令：

之后别的设备会看到登录页；这台机器上的浏览器照样直接进。没设口令时，只要从别的机器打开看板，每个页面都会显示一条红色警告。要让看板在本机以外也能访问， 就同时设好 JOB_RADAR_WEB_BIND（比如 0.0.0.0）和口令，否则 doctor 会报错。会话、锁定和其他细节见 configuration.zh.md。

9. 全面体检

Section titled “9. 全面体检”

它逐项检查 Docker、四个服务、数据库、runner 和 AI worker 的心跳、AI 登录、Telegram、Tailscale、备份、磁盘空间、每个已开启的来源 和你的配置，用 ✅ / ⚠️ / ❌ 标出来，每个问题下面写着该怎么做。它只读不写：不调用 AI、不发 Telegram、不花钱。注意写成 pnpm run doctor：单写 pnpm doctor 是 pnpm 自己的命令。退出码：0 全部 ✅，1 有 ⚠️，2 有 ❌，3 doctor 本身没能运行。

刚装好时有几项会给警告，等你配好就没了：Tailscale 和公开地址（⚠️）；出厂就开着的付费渠道（linkedin-brightdata、 linkedin-apify、tavily），在你填 key 或关掉之前；上一轮和上次备份，在第一轮、第一次备份之前；worker 在终端里跑而没装成服务时还有 aiworker.launchd（在 Linux 上这一项读的是 systemd 用户单元）。LinkedIn 是可选的：一个 LinkedIn 渠道都没设置时，LinkedIn 那一行会这么写， 仍是 ✅。在 Linux 上，data/ 下有文件不归 PUID 所有时，data.ownership 会警告。没打开的 Telegram 推送不会报。浏览器里 /sources 页显示同样的健康状态，包括 AI worker 卡片。

第一轮可以在向导的回顾步骤里跑，也可以在 设置 → 手动操作 → “立即跑一轮” 里跑。之后按 schedule.yaml 里的时间自动跑 （默认工作日 07:00 和 17:00、周末 09:00，按你的时区）。

升级

Section titled “升级”

发布版本是 git 标签 vX.Y.Z。升级前先看更新日志里那一版写了什么：需要你手动做的事会写在里面。

部署脚本会依次：检查工具、切到这个标签、装依赖、迁移你的配置文件（原文件留在 data/config/.backup/）、备份数据库、重建镜像、 等正在跑的轮次结束、重启服务、迁移数据库（迁移前自己再备份一次）、重启 AI worker 服务、跑 doctor。哪一步失败就停在哪一步，并告诉你该怎么办； 每一步都可以重复执行。

AI worker 这一步会重新安装第 5 步的服务（macOS 上是 launchd，Linux 上是 systemd 用户单元）。如果 worker 由你自己的进程管理工具在跑， 加上 --no-ai-worker，升级完自己重启它。

想退回去，就部署上一个标签：scripts/ops/deploy.sh --ref <上一个标签>。如果你要离开的那一版迁移过数据库，还要恢复升级时自动做的那份备份。 在 Linux 上从容器以 root 运行的旧版本升级，要先修正一次文件归属。详见 upgrade.zh.md、deploy.zh.md。

备份

Section titled “备份”

runner 每天夜里（默认 03:30）备份到 data/backups/：一份数据库 dump，加一个 .config.tgz，里面是你的配置（data/config/）和画像 （data/profile/）。保留最近 14 天每天最新的一份，和最近 8 周每周最新的一份。数据库迁移前它会额外做一份安全备份，备份成功了才迁移。 .env 和 .auth/ 不在任何备份里：自己留一份。

真正恢复（--target jobradar --yes，配置和画像也要恢复的话再加 --with-config）时，先恢复到临时数据库，再停掉 web、runner 和 AI worker， 通过改名把两个数据库对调，然后全部重新启动。原来的数据库留作安全副本，选错了文件也能撤回。

data/backups/ 在项目目录里。想防硬盘坏掉，把它纳入你自己的备份流程，拷到别处；.config.tgz 要当密钥一样对待（里面可能有代理凭据）。 恢复的全部细节见 backup-restore.zh.md。

永远不要执行 docker compose down -v：-v 会删掉数据库卷。停服务用 docker compose stop 或 pnpm stack:down。

卸载

Section titled “卸载”

这会删掉数据库、你的画像、配置和登录状态，无法撤销。 先做最后一份备份并拷到安全的地方（scripts/ops/backup.sh，然后拷走 data/backups/；以后可能还会回来的话，data/profile/ 和 data/config/ 也留一份）。

docker image prune 可以删掉构建出的镜像。如果你为 Job Radar 设置过登录时启动 Docker、电源设置或 Tailscale，请手动改回去。 你的 claude 和 codex 登录是你自己的，会保留。详见 upgrade.zh.md。

常见问题排查

Section titled “常见问题排查”
你看到 怎么办
pnpm doctor 输出的是 pnpm 自己的检查 用 pnpm run doctor。
Cannot connect to the Docker daemon 启动 Docker：macOS 上 open -a Docker，Linux 上 sudo systemctl start docker。
docker compose 不认 env_file 或 required 你的 Compose 低于 2.24，升级 Docker Desktop 或 compose 插件。
端口被占用 在 .env 里换端口：看板用 JOB_RADAR_WEB_PORT（默认 3000），数据库用 DB_HOST_PORT（默认 5433）。然后 docker compose up -d。
向导提示保存失败（Linux） data/ 不归容器运行的那个用户所有。在 .env 里把 PUID / PGID 设成 id -u / id -g，执行一次 sudo chown -R "$(id -u):$(id -g)" data .auth，再 docker compose up -d。doctor 的 data.ownership 会列出哪里不对。
/sources 上的 AI worker 卡片显示“无响应” pnpm ai-worker（或 launchd / systemd 服务）在跑吗？看它的日志（macOS 是 data/logs/ai-worker.err.log，systemd 是 journalctl --user -u job-radar-ai-worker）。
岗位进来了，但一直没分数 检查 claude auth status / codex login status，再跑 pnpm ai:probe。doctor 里 ai.profile 是 ❌ 的话，打开 /me 填上简介或技能：没有画像就不打分。
another ai-worker is running against this database 已经有一个在跑了（通常是 launchd 或 systemd 服务）。这没问题；想手动跑一个，先把它停掉。
什么都没采集 完成或跳过设置向导；doctor 的 setup.completed 和 cycle.last 会说明 runner 在等什么。
某个来源显示“未配置” .env 里缺它的 key。补上后执行 docker compose up -d，或者把这个来源关掉。
出现了你没想到的登录页 .env 里设了口令（JOB_RADAR_WEB_PASSWORD_HASH）。登录，或者删掉这一行再 docker compose up -d web。如果怎么都登不进去，多半是哈希没复制完整：重新运行 pnpm web:password。
421 Misdirected Request 你用了看板不认识的主机名访问。用 127.0.0.1、*.ts.net 地址，或把名字加进 JOB_RADAR_ALLOWED_HOSTS。
pnpm telegram:test 报 chat not found chat id 不对，或者你还没在 bot 里点 Start。
Telegram 按钮点了没反应 别的程序在用同一个 bot token（runner 日志里 getUpdates 返回 409）。给 Job Radar 单独建一个 bot。

还是解决不了？运行 pnpm run doctor --json，去掉个人信息后提 issue。日常使用、各页面和日志见 usage.zh.md。
