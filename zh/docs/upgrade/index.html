升级、回滚与卸载

Job Radar 从一个 git 检出目录运行。发布版本是签名的 git 标签 vX.Y.Z（见更新日志）。如果你只是使用它，请停留在发布标签上，从一个标签升级到下一个；main 是开发分支，两次发布之间可能变化。

升级到某个发布版本

Section titled “升级到某个发布版本”

把 v2.0.0 换成你想要的版本（git fetch --tags && git tag --list 'v*' 列出所有版本）。先读那个版本的更新日志：它会写明你是否需要手动做什么。

--ref 可以是标签或分支。检出会停在那个提交上（对标签来说 git 称之为 detached HEAD，这是正常的）。不加 --ref 时脚本跟随 main。

部署默认不验证签名。加 --verify 会先对标签运行 git verify-tag，无效就停止。它用的是随仓库发布的维护者公钥 signing-key.pub（allowed_signers 格式；指纹 SHA256:HHRRfExpbUjcK0/pdc5E1qf94ogkREVkt9+1VP58JQc，SECURITY.md 里也有）；你自己用 git config gpg.ssh.allowedSignersFile 设置的公钥列表优先。有签名密钥时发布会签名，见 RELEASING.md。手动检查：git -c gpg.format=ssh -c gpg.ssh.allowedSignersFile=docs/signing-key.pub tag -v v2.0.0。

部署脚本做了什么

Section titled “部署脚本做了什么”

按顺序执行，遇到第一个失败的步骤就停下：

  1. 预检：git、docker、node、pnpm 已安装，Docker 正在运行。
  2. 检出：获取标签和分支并切换到 --ref（检出目录不干净时拒绝运行）。
  3. 按锁文件安装依赖。
  4. 配置：创建 data/ 目录，复制你还没有的配置文件，迁移格式有变化的配置文件（原件保存在 data/config/.backup/）。
  5. 备份：数据库在运行时先做一个 pre-deploy 备份到 data/backups/。备份失败会中止升级。
  6. 构建镜像。
  7. 排空并重启：有限时间内等待正在运行的周期结束，然后重建容器并等待它们健康。
  8. 清理 Docker 构建缓存和悬空镜像（不动数据卷）。
  9. 迁移数据库（runner 启动时也会做）。有待执行的迁移时会先做一份 premigrate 备份，备份失败就不迁移。
  10. ai-worker：重装或重启主机 AI worker 服务：macOS 上是 launchd 代理，Linux 上是 systemd 用户单元 job-radar-ai-worker.service（没有 systemd 用户管理器时不安装任何东西，脚本会说明）。
  11. doctor：pnpm run doctor 报告需要关注的事项。

细节和选项见 deploy.zh.md。
