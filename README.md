# Job Radar website

The website of [Job Radar](https://github.com/Joevonlong/job-radar): a landing page, a tutorials page and the product
guides, in English (default, `/`) and Chinese (`/zh/`), published with GitHub Pages at
<https://joevonlong.github.io/job-radar-site/>.

Built with [Astro](https://astro.build/) 7 and [Starlight](https://starlight.astro.build/) for the docs section. Styled
with the product's design system v3 (paper light theme, terminal dark theme) and the final brand kit.

## Develop

Requirements: Node 22 and pnpm 11 (the version is pinned in `package.json` → `packageManager`).

```bash
pnpm install          # to use a package store of your own: --store-dir <dir> or the pnpm_config_store_dir variable
pnpm dev              # http://localhost:4321/job-radar-site/
pnpm build            # static site in dist/
pnpm preview          # serve dist/ locally (stop a background one: pnpm exec astro preview stop)
pnpm check:links      # every internal link, asset and #anchor in dist/ resolves (CI runs it too)
pnpm shots            # screenshots of the built site into .shots/ (1440 / 768 / 390 px, light and dark, en and zh)
pnpm fetch:media      # download the published videos into public/media/ (see "Videos")
```

`pnpm shots` saves a viewport shot (`*-view.png`, what a visitor sees on arrival) and a full-page shot of every page,
and reports layout shift, horizontal overflow, images without `alt` and console errors.

## Layout

```text

src/data/videos.json      every video slot: id, titles, descriptions, media paths (written by pnpm sync:media)

src/data/install.ts       the install commands shown on the landing page
src/data/docs-nav.mjs     how the synced guides are grouped in the docs sidebar, and their short labels (en + zh)
src/data/docs-sync.json   which product commit the docs come from (written by pnpm sync:docs)
src/components/landing/   hero, ticker, pillars, feature gallery, how it works, install, privacy, FAQ
src/components/           header, footer, video slot, player dialog, theme toggle, language switch
src/components/starlight/ Starlight overrides: head (font preloads), header links, footer note
src/content/docs/         GENERATED by pnpm sync:docs: never edit by hand
src/content/i18n/         a few Starlight UI strings worded for this site
src/styles/               tokens.css (design system v3 + brand), site.css, starlight.css, fonts

scripts/                  sync-brand, sync-media, fetch-media, media-release-notes, sync-docs, check-links, shots
```

## Content

**Copy.** Everything on the landing, tutorials and 404 pages is in `src/i18n/ui.ts`, English and Chinese side by side.
The taglines are final; claims must match the product docs (no unreleased features).

**Docs.** `pnpm sync:docs` copies the product repository's `docs/*.md` (English) and `docs/*.zh.md` (Chinese) into
`src/content/docs/`, takes each page's first heading as its title, drops the `[English] | [中文]` line, turns links
between guides into site links, links other repository files to GitHub, and gives each page an edit link to its source.
By default it reads `../job-radar` (a checkout of the product repository next to this site); use
`--from <checkout>` or `JOB_RADAR_DIR` elsewhere, and `--check` to fail when the synced copy is out of date. It also
updates the "Docs synced from" line above. A guide that is not listed in `src/data/docs-nav.mjs` shows up under
"More guides"; a guide without a Chinese file shows the English text on the Chinese side (Starlight's fallback notice).
The sidebar uses the short labels in `SHORT_LABELS` (same file, English and Chinese); the page titles stay the
product's own.

**Videos.** Every slot reads `src/data/videos.json`. The video files themselves are **not in git**: they are assets of
GitHub Releases of this repository, and `src/data/media.lock.json` (committed) lists each one with its size, sha256,
duration and release tag.

- `pnpm sync:media` (maintainers; needs the exports folder, `--from <dir>` or `SITE_MEDIA_DIR`) copies finished exports
  (`<dir>/export/<ID>/<ID>.web.mp4`, `.webm`, `.poster.jpg`, and the captions `<ID>.{en,zh}.vtt` next to them or in
  `<dir>/subs/`) into `public/media/<ID>/`, makes WebP poster sizes,
  updates `videos.json` (status `ready`, dimensions, duration) and the lock. Files that are new or changed get the
  release tag of the day (`media-YYYY-MM-DD`, `mediaTag` in `site.config.mjs`, or `--tag`); unchanged files keep
  theirs. Ids without an export stay `coming-soon`. Budgets: short clips ≤ 6 MB per file,
  full videos ≤ 60 MB (`--strict` fails over budget).
- `pnpm media:release-notes` prints, per release tag, exactly which files to attach and the `gh release create` /
  `gh release upload` commands (`--check` asks GitHub which are there already, `--markdown` gives a table).
- `pnpm fetch:media` downloads every file in the lock from `MEDIA_URL` (`site.config.mjs`, default
  `https://github.com/Joevonlong/job-radar-site/releases/download/{tag}/{file}`), checks sha256, and exits 1 naming the
  release of anything missing or different (`--allow-missing` only warns). With `GITHUB_TOKEN` set it also reads
  releases of a private repository. The deploy workflow runs it before the build.
- A slot whose files are not in `public/media/` (not synced, not fetched) shows the coming-soon poster, so a fresh
  clone builds without any media.

Short clips preview muted on hover; a click plays them with sound and captions in a dialog (English captions on `/`,
Chinese on `/zh/`). Full videos play in place. To add a new id, add an entry to `videos.json` (copy an existing one),
run `pnpm sync:media`, commit `videos.json` and `media.lock.json`, and upload the new files
(`pnpm media:release-notes`).

**Brand.** `pnpm sync:brand` (maintainers; `--from <dir>` or `SITE_BRAND_DIR`) copies the final logo, favicons and
social image from the brand kit unchanged. `pnpm sync` runs all three syncs.

**Local settings.** The sync scripts read optional per-machine paths from a git-ignored `.env.local` in the site root
(`SITE_BRAND_DIR`, `SITE_MEDIA_DIR`, `SITE_MEDIA_MANIFESTS`, `SITE_BROWSERS_DIR` for a local Playwright browsers folder
used by `pnpm shots`). None of them is needed to build the site.

**Install block.** The commands on the landing page live in `src/data/install.ts` and must stay identical to the product
README's Quick start. The release they check out is the single constant `RELEASE_TAG` there; change that one line after
a product release.

## Deploy

`.github/workflows/deploy.yml` builds the site and publishes it with the official `actions/upload-pages-artifact` +
`actions/deploy-pages` flow (actions pinned by commit SHA). It runs on every push to `main` once the repository exists:

1. Create the GitHub repository `Joevonlong/job-radar-site` and push `main`.
2. Upload the media releases: run `pnpm media:release-notes` in a checkout that has the files in `public/media/` and
   run the `gh release create …` commands it prints (releases must be published, not drafts).
3. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
4. Actions → Deploy to GitHub Pages → Run workflow (or push to `main`) publishes the site.

The synced docs are committed; the videos come from this repository's releases (`pnpm fetch:media`, which fails
the deploy if a file listed in the lock is missing). The run triggered by the very first push therefore stops at
"Fetch media" until step 2 is done; run the workflow again after step 3.

**Custom domain.** Change `SITE_URL` in `site.config.mjs` (for example `https://jobradar.example.org/`; the base path
follows from it), set the domain under Settings → Pages, and push. With a custom domain `robots.txt` is served at the
domain root and takes effect; on `*.github.io/job-radar-site/` crawlers ignore it (the sitemap is still linked from
every page).
